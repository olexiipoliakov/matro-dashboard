# Переїзд з GitHub Pages на Render.com

Ціль: дашборд закритий паролем, Bitrix-дані оновлюються майже миттєво
(вебхук), Meta/GSC/Bitrix (як підстраховка) — раз на 3 години.

## Крок 1 — акаунт на Render

1. **render.com** → Sign Up (можна через GitHub — простіше)
2. Дай Render доступ до репозиторію `matro-dashboard` (він попросить при
   першому підключенні)

## Крок 2 — створити сервіс з render.yaml

1. У Render: **New → Blueprint**
2. Вибери репозиторій `matro-dashboard`
3. Render сам знайде `render.yaml` і запропонує створити сервіс
   `matro-dashboard` — підтверджуй
4. **Важливо**: перевір, що обраний план — **Starter** (не Free!) — на
   Free сервер засинає через 15 хв без запитів, і вебхук з Bitrix або
   загубиться, або прийде із затримкою ~30-60с на "прокидання"

## Крок 3 — секрети (Environment)

У Render: сервіс `matro-dashboard` → **Environment** → додай значення для
кожної змінної (сам список полів Render вже створить з `render.yaml`,
залишиться тільки вписати значення):

| Змінна | Що вписати |
|---|---|
| `DASHBOARD_USER` | будь-який логін, наприклад `matro` |
| `DASHBOARD_PASSWORD` | придумай надійний пароль — саме він захищає весь дашборд |
| `BITRIX_INCOMING_WEBHOOK_SECRET` | токен, який Bitrix видасть на кроці 5 нижче (поки що онов не існує — впишеш пізніше і зробиш Redeploy) |
| `BITRIX_WEBHOOK_URL` | той самий вхідний вебхук Bitrix, що вже використовувався в GitHub Secrets |
| `META_ACCESS_TOKEN` | той самий токен Meta, що й був |
| `META_ACCESS_TOKEN_MATRO` | той самий токен Matro, що й був |
| `META_ACCOUNT_ID` | той самий |
| `META_ACCOUNT_ID_2` | той самий |
| `GSC_SERVICE_ACCOUNT_JSON` | той самий JSON-ключ сервісного акаунту Google |

Значення всіх токенів можна просто скопіювати з GitHub → Settings →
Secrets and variables → Actions (там вони збережені, хоч і не видно
самого значення — якщо не зберігав їх окремо, доведеться перегенерувати
заново так само, як і раніше для GitHub).

## Крок 4 — деплой

Після заповнення секретів Render сам задеплоїть сервіс. Перевір лог
(**Logs** у Render) — має з'явитись щось на кшталт:
```
[scheduler] запускаю fetch_meta.py…
```
Це перший автоматичний прогін одразу при старті.

Адреса дашборду буде виглядати як `https://matro-dashboard-xxxx.onrender.com`
(Render видає домен автоматично; пізніше можна підключити свій).

## Крок 5 — вихідний вебхук у Bitrix24 (для миттєвого оновлення)

1. У Bitrix24: **Налаштування → Розробникам → Інше → Вихідний вебхук**
2. Обробник (URL): `https://<твій-домен-render>.onrender.com/webhook/bitrix`
3. Обери події: `OnCrmDealAdd`, `OnCrmDealUpdate`, `OnCrmLeadAdd`, `OnCrmLeadUpdate`
4. Bitrix видасть **токен додатку** (application_token) — скопіюй його
5. Встав цей токен у Render як значення `BITRIX_INCOMING_WEBHOOK_SECRET`
   (Environment → онов значення → Save, Render сам передеплоїть)

Тепер при кожній зміні угоди/ліда Bitrix сам "стукне" на сервер, і
`bitrix_data.json` оновиться за секунди (з дебаунсом в 1 хвилину, якщо
подій багато підряд).

## Крок 6 — перевірка

1. Відкрий адресу дашборду в браузері — має спитати логін/пароль
2. Введи `DASHBOARD_USER`/`DASHBOARD_PASSWORD`, які задав на кроці 3
3. Зміни щось у Bitrix (наприклад, суму угоди) і зачекай ~10-15 секунд —
   онови сторінку `bitrix.html`, дані мають підтягнутись без ручного
   запуску чогось

## Крок 7 — вимкнути стару схему (GitHub Actions)

Коли переконаєшся, що Render працює стабільно кілька днів:

1. У GitHub-репозиторії: **Actions → update** → **⋯ → Disable workflow**
   (не обов'язково видаляти файл — просто вимкнути, щоб два джерела не
   писали в один git-репозиторій одночасно)
2. GitHub Pages можна залишити вимкненим у Settings → Pages, якщо більше
   не плануєш ним користуватись

## Що НЕ змінюється

- Уся бізнес-логіка (`fetch_meta.py`, `fetch_gsc.py`, `fetch_bitrix.py`,
  методика категоризації) — та сама, без змін
- Самі сторінки дашборду (`home.html`, `index.html`, `seo.html`,
  `bitrix.html`) — ті самі файли, просто тепер віддаються через `app.py`
  замість прямої статики GitHub Pages
